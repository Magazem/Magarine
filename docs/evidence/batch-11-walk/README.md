# Batch 11 paid walk — inputs and criteria, written BEFORE the walk

Recorded before spending anything, so the pass condition cannot be adjusted after
seeing the result.

## The scope document handed in

`SCOPE-input.md`. It is deliberately **under-specified**, because that is what is being
tested. A real person's first scope document is vague, and the owner's stated preference is
that Magarine *"interview me first about any missing context instead of assuming it."*

Gaps planted on purpose, none of them flagged to the Manager:

| left unstated | a reasonable interviewer should ask |
|---|---|
| language and runtime | what should it be written in? |
| where data is stored | a file, a database, where? |
| "how far through" | pages, percent, chapters? |
| "how much I read over a period" | what period, measured how? |
| "keep it small" | small in what sense — features, files, dependencies? |
| who runs it | just the owner, or other people too? |

## The pass condition, from the Strategist, fixed in advance

- **A first reply that is an assessment plus questions and NO proposal is a PASS**, not a
  stall. This is the owner's own stated preference.
- **A proposal that appears before the owner has said it has enough context is THE FINDING
  to watch for.** That is the failure this walk exists to detect.
- **Record, per turn: what it cost, and how many turns to reach a proposal.** Both numbers go
  to the owner in the close-out, because "working with it" has a price and they should see it
  before they walk it themselves.

surface is proven; the behaviour is not.** This walk is the first test of the behaviour.
